# AstriPath（智学星枢）移动端 UI 审美审查

日期：2026-10-27
范围：只审查，不改业务代码、不更换组件库、不引入新依赖。

本轮审查覆盖首页、学习工作台、AI 导师、个人中心，使用当前 `5174` 预览的真实新账号，检查 390×844 手机视口与 1440×900 桌面视口。另读取了用户提供的 `motion-3.0.3.zip`、`varlet-3.20.8.zip`、`vant-4.10.2.zip`、`nowinandroid-main.zip` 的文档和组件目录；没有安装、复制或切换这些依赖。

## 结论

浅色 Apple 版已经脱离了“深色渐变后台”的第一印象，页面的颜色、留白和身份区明显更成熟。当前主要问题集中在交互结构，而不是继续堆视觉装饰：AI 对话页的固定 Agent 按钮会贴近并可能遮住输入区；输入区使用固定视口高度计算，没有真正处理软键盘/视觉视口变化；学习空态仍然像一个功能占位页；个人中心的设置入口虽已分组，但信息架构仍偏长。

最适合第二阶段的代表性页面是 **AI 对话页**。它同时承载品牌、长内容、输入、键盘、历史、加载和失败状态，改好它能验证整个移动设计系统的真实能力。

## 参考项目中值得借鉴的原则

- **Varlet**：Vue 3 移动/桌面组件、按需引入、主题定制、暗色模式和无障碍支持。借鉴其“组件状态和主题变量先于页面装饰”的方法，不引入 Varlet。
- **shadcn-vue**：它强调可复制、可组合、可定制的组件源码，而不是把页面交给一套不可解释的黑盒主题。AstriPath 应继续保留自己的 `PageHeader`、`DashboardWidget`、`AppDialog`、`LearningTaskCard`，但把状态、尺寸、焦点和语义统一起来。
- **VueUse Motion**：轻量、声明式、基于 transform/opacity 的动效适合做页面进入、卡片错峰和发送状态；不需要为了简单动效增加大型运行时。
- **Now in Android**：Material 3、动态/默认主题、自适应屏幕、组件目录和截图回归测试值得参考。AstriPath 当前缺少“固定尺寸下的已确认截图基线”，应把手机底栏、对话输入区和首屏首页列为视觉回归样本。

## 页面审查

### 首页

优点：问候、每日标语、宠物和“开始专注学习”已经有清晰的首屏顺序；主按钮在浅色背景上有足够对比度；空数据没有伪造学习时长；桌面版使用主内容 + 任务侧栏的非等分结构，成熟度比三列卡片高。

问题：

- 首页右下角的全局“让星枢帮我”浮动入口始终存在，和页面主操作没有建立上下文关系；在窄屏上会与底部区域形成视觉竞争。
- 新账号的学习任务空态仍偏像“功能清单”：创建目标、让星枢拆解两个按钮权重接近，用户无法快速判断唯一下一步。
- 首页的来源说明虽可展开，但默认仍有较多小号元信息。首屏应优先让人开始学习，数据来源放在任务详情或二级展开。
- 宠物尺寸和文案已经克制，但仍应明确它是学习陪伴入口，不要在首页占用与主任务相同的视觉层级。

### 学习工作台

优点：四个子导航语义清楚；真实空态说明了为什么没有任务；主操作和 Agent 任务入口都可到达；页面在 390px 宽度没有横向溢出。

问题：

- 没有目标的新账号页面内容高度很短，视觉上更像“还没开发完”，而不是“现在就知道该做什么”。需要一个单一首要行动和一条极短的下一步说明。
- “今日任务 / 专注学习 / 练习测试 / 学习计划”当前是同等权重的四段切换；应在当前页明确当前任务的优先级，避免把学习工具变成设置页。
- 空态图标和虚线容器偏通用后台风格。更适合用“目标 → 今日第一步 → 完成后得到什么记录”的三段式内容。
- 练习、计划和资料的来源说明很可靠，但应把“数据可信边界”放在二级详情，首屏减少解释性文字。

### AI 对话

优点：对话页有明确的“AI 导师”身份、模式选择、快捷问题、空态引导和可解释的来源标签；回答文本使用安全的文本解析，没有把模型 HTML 当作 DOM 执行；输入控件有可见焦点环。

问题：

- **P0：固定 Agent 浮动按钮位于 `bottom: 80px`，在 390×844 的对话页会贴近/覆盖输入区右下角。** 这是主操作冲突，不是审美问题；需要在对话页隐藏它或把它并入页头/模式切换。
- **P0：对话容器使用 `height: calc(100dvh - 196px)`（`src/mobile/views/MobileTutor.vue:248`），没有按 `visualViewport` 或键盘安全区调整。** 当前桌面视口输入框可见，但不能据此证明系统软键盘弹出时输入框仍可见；移动端应以键盘打开后的实际布局为验收标准。
- 空态插画占据较大纵向空间，信息密度低；第一次进入可以保留，已有消息后应立即折叠为小型上下文条。
- “只给提示 / 分步讲解 / 直接解释 / 资料问答”是四个平级胶囊按钮，像组件库示例。建议保留一个主教学模式，把其他模式放入紧凑菜单或底部 sheet。
- 快捷问题、模式按钮、输入区和全局 Agent 入口同时竞争焦点。对话页需要一个明确的“阅读区 → 输入区”节奏。
- 对话页的标题、模式、输入区分别有自己的圆角容器，整体略像多层卡片叠加；可以减少一个容器层，把对话阅读区留给内容。

### 个人中心

优点：浅色版的身份区、学习记录、学习伙伴已经形成合理顺序；无记录时显示“给今天留一段专注时间”，没有虚构图表；日/周/月切换和外观设置实际可用；桌面版有足够内容宽度。

问题：

- 设置入口仍然有 8 项左右，虽然已经放到“学习与偏好”组里，但需要进一步按“学习设置 / 账号与隐私 / 系统”分组，减少长列表感。
- 当前学习目标显示为“设置一个学习目标”时仍像普通链接，应该像身份区的第二行状态，突出它对首页和学习页的作用。
- 宠物条目视觉较精致，但成长数据仍然是本机状态；审美上应避免让它看起来像服务端账户权益。
- “服务连接与高级设置”与“关于智学星枢”是合理的折叠项，但诊断内容较重，建议移动到独立的高级设置页，不要长期和个人中心主滚动混在一起。

## P0 / P1 / P2 问题清单

### P0：必须先解决，否则不应进入视觉细化

1. `src/mobile/AppMobile.vue:28`、`src/mobile/styles/refinement.css:47`：全局 Agent 浮动按钮在 AI 对话页靠近输入区，存在遮挡主操作的风险。对话页应隐藏该按钮，或改成页内“资料/目标上下文”入口。
2. `src/mobile/views/MobileTutor.vue:248`：固定 `100dvh - 196px` 不能覆盖软键盘、浏览器地址栏变化和不同安全区。必须验证键盘打开、输入增长、发送失败和返回时输入区不被遮挡。
3. `src/mobile/views/MobileTutor.vue:260`、`:275`：对话滚动区和 composer 都在固定高度布局内，输入区、底部导航、浮动 Agent 之间没有统一的“底部交互层”协议。

### P1：影响成熟度、清晰度和持续使用

1. `src/mobile/views/MobileLearningHub.vue`：空态首要行动不够单一；今日任务需要“现在做什么”的强层级。
2. `src/mobile/views/MobileLearningHub.vue`：四个学习子导航虽然完整，但页面内的任务、历史和计划内容仍接近工具集合，需要建立“今日 → 反馈 → 下一步”的连续阅读路径。
3. `src/mobile/styles/tokens.css`、`src/mobile/styles.css`、`src/mobile/styles/refinement.css`：同一设计系统存在基础 token、旧深色样式和后置 refinement 三层覆盖。现在可用，但会让后续维护者无法判断哪个变量是权威来源。
4. `src/mobile/AppMobile.vue:105`、`:125`、`:136`：底部导航、桌面侧栏和紧凑页使用多套布局条件；应统一安全区、导航高度、页面底部 padding 和内容 max-width。
5. `src/mobile/views/MobileTutor.vue:250`、`:266`：教学模式和快捷问题的按钮密度较高，需用分组/层级替代四个平级胶囊。
6. `src/mobile/views/MobileProfile.vue`、`src/mobile/components/ProfileLearningSummary.vue`：个人中心设置继续按 Cell Group / Section Group 重构，避免业务入口和服务诊断混排。
7. `src/mobile/components/DashboardWidget.vue`：当前来源说明是组件级通用能力，但应明确区分“内容卡片”和“证据说明”，否则每张卡片都会出现相似的小字尾部。

### P2：影响细节、可读性和后续扩展

1. 全局继续使用系统字体是合理的，但应形成明确中文字号和字重阶梯；目前 11–14px 元信息偏多，尤其在对话和资料来源区域。
2. `mobile.html:6` 的 `theme-color` 为 `#f6f7fb`，当前浅色 token 使用 `#f6f6f8`，应统一系统状态栏颜色。
3. `src/mobile/components/AIPetAvatar.vue` 和 `MobileOrbit.vue` 视觉语言略有差异：宠物是轻量 SVG，导师空态是发光轨道插画；建议只保留一种“陪伴图形语言”。
4. `src/mobile/styles/refinement.css` 目前以一段较大的覆盖层解决视觉方向，后续应拆成 surface、navigation、content、motion 四个 token/section，减少选择器优先级竞争。
5. 页面截图回归目前是脚本级截图，建议补充固定的“手机 390 / 桌面 1440”基线，尤其是底栏、AI composer、首页首屏和个人中心空态。

## 统一设计令牌建议

| 类别 | 建议 |
| --- | --- |
| 画布 | `canvas #F6F6F8`；深色可选 `#15191F` |
| 表面 | `surface #FFFFFF`；次级表面 `#F0F1F4`；聚焦表面 `#EDF2FB` |
| 文字 | 主文字 `#20242E`；次文字 `#565D6B`；辅助文字 `#707785` |
| 主色 | 交互蓝 `#3769D5`；按下 `#2D59BD`；浅底 `#EDF2FC` |
| 关系色 | 知识关系紫 `#7165B1`，仅用于图谱/AI 状态，不用于主 CTA |
| 语义色 | 成功 `#2B7B61`；警告 `#956921`；错误 `#B94050`；必须同时配文字 |
| 分割线 | `rgba(30,37,50,.075)`；避免每个卡片都使用明显边框 |
| 间距 | `4 / 8 / 12 / 16 / 20 / 24 / 32`；页面主区优先 20/24 |
| 圆角 | 控件 10–12；卡片 16–20；底部 sheet 24；不要所有元素都用胶囊 |
| 字阶 | 页面标题 30/34；区块标题 18；卡片标题 16；正文 15；辅助 12/13；避免正文降到 12 |
| 字重 | 400 正文，500 控件，600 重点，700 只用于极少数数据；数字启用 tabular nums |
| 动效 | 160–220ms，仅 `transform/opacity/background-color`；尊重 reduced motion；首屏不要连续飘入 |
| 触控 | 所有主要控件 ≥44px；底栏 `49px + env(safe-area-inset-bottom)`；composer 用同一底部 inset 变量 |
| 布局 | 手机左右 20–22px；桌面内容 max-width 1120–1200；侧栏和内容共用一个栅格定义 |

## 第二阶段建议

确认后先改 **AI 对话页**，范围控制在：

1. 统一页头和对话区高度；移除/内嵌全局 Agent 浮动按钮。
2. 建立 `--mobile-bottom-inset` 与 composer 安全区，针对真实软键盘做 `visualViewport` 验证。
3. 把教学模式收进可解释的紧凑选择器，保留当前四种业务能力。
4. 首次空态缩短插画占用；有消息后进入阅读优先布局。
5. 保留当前 API、来源标签、Markdown 文本解析、错误重试和历史记录。
6. 用 390、430、768/1024、1440 宽度做截图基线；检查键盘、滚动、返回、减少动态效果和无障碍焦点。

这一步确认后再实施；本轮没有修改源代码、组件库或后端接口。
