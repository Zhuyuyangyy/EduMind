## 迁移前需要处理的具体问题

1. **学习对话不能直接搬请求代码。** `useChatApi.ts` 当前使用相对地址 `/api/chat` 裸 `fetch`，移动端需要经过共享 API 客户端处理绝对服务地址、Bearer、CSRF 与错误。`src/lib/api.ts` 已有聊天请求方法可供整合。
2. **资源生成存在契约不一致。** `ResourceGeneratePanel.vue` 调用无参数 `generateResources()`；当前 `server/index.js` 已要求 `topic` 和 `resourceType`。应先形成有效输入流程，并验证错误处理，而不是直接复刻按钮。
3. **演示数值与真实学习证据需要区分。** `useReverseUpdate.ts` 有固定证据数量和画像前后值；`TrainFlow.vue` 有固定站点/流程内容；`Tutoring.vue` 提交样例路径，并用答案长度构造正确率。迁移时保留功能目的，采用真实学习事件和服务端评分。
4. **资源、笔记和收藏不等于已经支持跨端同步。** `EduMind.vue` 引入初始资源和推荐数据；课程含 localStorage 状态；笔记、收藏等视图存在前端初始化集合。需要核对各项持久化范围，不能直接承诺账号云同步。
5. **设置项不能以展示数量作为验收。** 网页设置目前持久化的是昵称；其他多个开关属于页面状态。App 的学习偏好同样仍有示例。新增设置必须明确保存位置与实际效果。
6. **生产环境已有数据边界。** 当前后端对演示评估、演示路径和演示工作流接口实施生产禁用。手机端需要呈现真实空态/错误，不得为填满页面静默替换为样例成绩。

以上均为代码检查发现，具体运行表现需在实施前后分别验证。

## 建议采用的对齐方式

- **推荐：共享业务能力，按手机交互实现页面。** 保留 Vue + Capacitor 和移动端入口，复用认证、API、类型和可复用业务逻辑；通过同账号数据和操作结果验收。
- **直接套用网页页面：** 初期页面迁移较快，但桌面布局、重型可视化以及裸请求等问题仍需处理，不能据此判定功能已适配。
- **重写独立 App 技术栈：** 需要重新承担认证、接口、学习状态和两端维护成本，目前没有发现必须重写的依据。

页面组织建议保持现有四个底部入口，补齐次级功能：今日学习承接画像引导及课程/资源入口；AI 导师提供需求采集与学习辅导两个明确入口；学习成长承接路径、分析、反馈和修订记录；我的承接学习档案、笔记、收藏与设置。页面分组属于建议，尚未新增或调整导航。

## 实施顺序建议

1. **画像与规划入口对齐：** 完整问卷、学习需求对话、画像报告与知识路径生成，先形成明确的学习起点。
2. **路径与资源对齐：** 知识点详情、课程/资源搜索和详情、带有效参数的个性化资源生成。
3. **辅导与反馈对齐：** 分步引导、真实练习结果、学习分析与有证据的画像更新；延用现有服务端练习机制。
4. **学习资产与设置：** 确认笔记、收藏、记录及偏好的持久化契约，再实现两端读写一致。
5. **设备验收：** 在可用 Android 设备上验证完整学习流程、键盘与返回键、冷启动、断网、401、账号切换与数据恢复。

每批验收至少包含：用户入口可达、真实 API 操作成功、同账号两端读回一致、其他账号不可见、失败状态明确、模型/规则降级有来源。构建和相关现有回归按改动范围执行，真机验收另记结果。
