# 注册 409 与登录恢复修复

用户实际报错：`请求失败（409） / 服务端返回了意外状态，请稍后重试。`

此前交付对注册异常流程的验证不完整；隔离环境的新账号正常注册通过，不能证明当前预览的重复账号与中断恢复流程已闭环。

## 根因与实际修复

现有服务器对重复账号返回 HTTP 409、`code: account-exists`。共享 API 客户端已保留状态码与错误码，但移动端错误展示忽略了它们的业务含义，落入通用错误分支，错误地建议稍后重试。注册页也没有提供有效的恢复主操作。

- `src/mobile/errors.ts`：根据 `account-exists` 明确提示账号已注册；账户、密码、昵称格式错误也返回具体规则。非注册的 409 不误报为账号存在。
- `src/mobile/views/MobileLogin.vue`：409 后保留账号和密码，切换登录状态，主按钮变为“用此账号登录”；仍调用原有登录接口校验密码。修改账号后清除过期的冲突提示。
- 注册已成功但后续登录失败时，明确显示“账号已创建，登录未完成”，用户可直接重试登录，不再重复注册。
- 提交时禁用字段与按钮，并增加提交中检查，避免连续点击或处理中改动账号造成混淆。
- 不修改后端账号规则、登录验证、已有账号、学习数据或支付逻辑。

## 回归证据

`scripts/mobile-auth-live-e2e.mjs` 直接连接用户实际预览的 `http://127.0.0.1:5174`，不另外启动测试服务；使用独立浏览器上下文和专门测试账号，不读取用户密码或保存凭据。

修复前精确复现同样的 409 错误文案，证据在 `outputs/auth-live-fix/baseline-409.json`；账号格式错误的证据在 `baseline-format.json`。

修复后验证 7 项：

1. 真实注册 201 → 登录 200 → 引导卡片 → 受保护首页/工作区 200。
2. 刷新后保持同一服务端会话。
3. 重复注册显示账号已注册，保留输入，主操作转为登录。
4. 点击“用此账号登录”可进入同一账号的首页。
5. 密码错误仍被拒绝，不能通过 409 恢复入口绕过认证。
6. 账号格式错误说明具体可修正的要求。
7. 已注册成功但自动登录被网络中断时，重试登录能继续，不再发送重复注册。

以上第 7 项通过浏览器主动中断登录请求检查恢复行为；注册、身份校验和工作区使用当前运行服务器的真实接口，没有伪造成功响应。
