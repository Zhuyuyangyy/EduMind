## 2. Qoder 执行的任务序列（关键提示词摘要）

1. **「按照任务书第 5.2 节做开发前审计」** → 审计报告 + 原工程测试 18/18 实跑取证。
2. **「把 EduMind 克隆到竞赛工作区并创建 competition/qoder-2026-studyhack 分支，与 main 及其他比赛隔离」** → 克隆 + 分支创建 + 推送 GitHub。
3. **「照搬智学星枢已有能力，做独立竞赛前端」** → 第一版：astripath 独立静态应用（Vue3 + 完整闭环 + 54 测试 + 部署）。
4. **「我个人感觉按照原来那个整体的界面就不错，这个改完就很普通了」** → 方向调整：保留原版界面。
5. **「我觉得吧你就按照原版的来那么多可视化啥的很好看的 D:\ZYY Project\EduMind」** → 同步本地最新工程树，将竞赛版重建为**原版应用 + 演示模式**。
6. **「你别做那么多呀上面的栏目你先按照原来的做」** → 顶部导航恢复原版 7 个栏目，竞赛入口收敛到首页横幅。
7. **「你那啥继续」** → 完成线上验收、文档更新与交付收尾。

## 4. Qoder 在测试中发现并修复的问题

**逻辑层（自动化测试暴露）：**
1. **计划算法缺陷**：薄弱知识点被先修链上无关知识点挤占 → 重写选点/排序（薄弱优先 + 先修闭包 + 链连续性）。
2. **导师检索误匹配**：长关键词子串误命中、单词命中低于阈值漏匹配 → 重构评分函数。
3. **诊断结果页分支错误**：提交后展示历史状态而非本次结果 → 修复模板分支顺序。
4. **练习证据未留痕**：未改变掌握度时「累计练习」不更新 → 修复为证据必留痕。

**重建后（构建 + 人工走查暴露）：**
5. **模板函数引用错误**：导入的函数当值用（恒真）导致答题页不显示 → 改函数调用。
6. **状态非响应式**：演示状态存于普通模块变量，打卡后界面不更新 → 增加响应式版本号。
7. **导师问答请求体形态不匹配**：对话 composable 发 `messages` 数组 → mock 兼容两种形态。
8. **Live2D 桌宠移动端遮挡**（真实 UX 缺陷）：浮动 canvas 拦截底部按钮 → 演示模式预置关闭桌宠 + 补 `scroll-padding-top`。

所有修复均先暴露问题、再定位根因，未使用任何「绕过测试」手段。

## 5. 如实声明的边界

- AI 导师为**演示模式**（预置课程知识库检索），不是实时大模型调用；原版 DeepSeek RAG 链路因竞赛版无后端、无 API Key 未接入，这是任务书允许的降级路径（已明示）。
- 掌握度为演示评估值，非真实学习能力测量（已明示）。
- AgentHub iframe 的 3D 模型经 meshopt 压缩（21.8MB→2MB）并打解码器补丁以满足部署体积限制；其 three.js 运行时来自 CDN（原版设计如此）。
- 本记录不夸大 Qoder 能力：Qoder 完成了工程实现、测试与部署；未参与的是比赛报名、人工方向决策与平台提交动作。
