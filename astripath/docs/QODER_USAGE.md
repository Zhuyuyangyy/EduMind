## 2. Qoder 执行的任务序列（关键提示词摘要）

以下为本次开发中向 Qoder 下达的核心任务（按时间顺序，均为实际执行）：

1. **「按照任务书第 5.2 节做开发前审计」** → 产出 `docs/AUDIT_REPORT.md`：检查仓库与分支状态、Web/Mobile 结构、后端 API、认证机制、RAG 与模型调用、测试情况、部署方式、可复用资产；并实跑原工程测试套件获取证据（18/18 通过）。
2. **「把 EduMind 克隆到竞赛工作区并创建 competition/qoder-2026-studyhack 分支，与 main 及其他比赛隔离」** → 完成克隆与分支创建，原工程零改动。
3. **「照搬智学星枢已有能力，做独立竞赛前端」** → 设计并实现 `astripath/` 独立静态应用（Vue3 + Vite + TS），复用数据组织与判分/画像规则。
4. **「实现学习诊断与知识画像，掌握度计算必须可解释并标注演示评估值」** → 8 题诊断 + 逐知识点正确率 + 画像分组 + 雷达图 + 变化流水 + 规则说明。
5. **「实现 7 天个性化学习计划，薄弱优先、考虑先修关系、可解释推荐理由、测试变化后重新规划」** → 计划算法经两轮迭代修复「薄弱点被无关知识点挤占」缺陷（见 §4）。
6. **「实现 AI 导师，优先复用 RAG 能力；不能伪装实时模型，必须标注演示模式并展示引用依据」** → 预置知识库检索 + 演示模式明示 + 引用依据 + 超范围降级。
7. **「实现针对性练习与学习反馈闭环，掌握度和计划必须真实更新」** → 即时判分 + 证据规则更新 + 计划自动重生成 + 学习报告。
8. **「补齐自动化测试：判分/映射/掌握度/计划/接口失败/持久化/重置/端到端」** → 43 单测 + 11 E2E 全通过。
9. **「部署到 Qoder Sites，公网无登录可访问」** → 准备/发布/公开访问策略/线上 11 项验收全通过。
10. **「撰写参赛材料：README、文档、测试报告、Qoder 使用记录、参赛帖子」** → 本目录全部文档。

## 4. Qoder 在测试中发现并修复的真实缺陷（非演示数据问题）

1. **计划算法缺陷**：薄弱知识点被先修链上无关知识点挤占（掌握度 10 的知识点排到第 5 天之后）→ 重写选点/排序算法，补充 3 个回归单测。
2. **导师检索误匹配**：长关键词子串匹配导致错误命中；单词命中低于阈值导致漏匹配 → 重构评分函数，补充回归单测。
3. **诊断结果页分支错误**：提交后展示历史状态而非本次结果 → 修复模板分支顺序，E2E 覆盖。

这些修复均先由自动化测试暴露、再定位根因修复，未使用任何「绕过测试」手段。

## 5. 如实声明的边界

- AI 导师为**演示模式**（预置课程知识库检索），不是实时大模型调用；原工程的 DeepSeek RAG 链路因竞赛版无后端、无 API Key 而未接入，这是任务书允许的降级路径（必须明示，已明示）。
- 掌握度为演示评估值，非真实学习能力测量（已明示）。
- 本记录不夸大 Qoder 能力：Qoder 完成了工程实现、测试与部署；未参与的是比赛报名、人工最终审核与平台提交动作。
