# 架构设计 · ARCHITECTURE

## 1. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│                        浏览器（评委设备）                      │
│                                                              │
│  Vue 3 SPA（hash 无关的 history 路由 + Qoder Sites SPA fallback）│
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐         │
│  │ 首页/课程 │ │ 诊断/画像 │ │ 计划/报告 │ │ 导师/练习 │         │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘         │
│       └────────────┴─────┬──────┴────────────┘               │
│                          ▼                                    │
│              Pinia Store（唯一状态源）                         │
│                          │                                    │
│         深度 watch → localStorage 持久化                      │
│                          ▼                                    │
│   ┌─────────────────────────────────────────────┐            │
│   │  logic/ 确定性纯函数层（可单测、无框架依赖）    │            │
│   │  scoring  mastery  plan  tutor  state        │            │
│   └─────────────────────────────────────────────┘            │
│                          ▼                                    │
│   ┌─────────────────────────────────────────────┐            │
│   │  data/ 演示数据（课程/题库/知识库，静态内置）   │            │
│   └─────────────────────────────────────────────┘            │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼
        Qoder Sites（静态托管 · SPA fallback · 公开访问）
```

无后端、无数据库、无外部 API：所有逻辑在浏览器内确定性执行，数据存于 localStorage。

## 2. 模块划分

### 2.1 数据层 `src/data/`

| 文件 | 内容 |
|---|---|
| `course.ts` | 演示课程与 8 个知识点（含先修关系、预计时长） |
| `diagnosis.ts` | 8 道诊断题（选项、答案、解析、知识点绑定） |
| `exercises.ts` | 24 道练习（按知识点分组） |
| `knowledgeBase.ts` | 8 张导师知识卡（关键词、讲解、示例、常见错误、引用依据、关联练习） |

### 2.2 逻辑层 `src/logic/`（纯函数，全部可单测）

| 文件 | 职责 | 关键规则 |
|---|---|---|
| `scoring.ts` | 判分 | 移植自原工程 `server/study/scoring.js`：选项下标严格相等；未知题型判错；会话汇总 |
| `mastery.ts` | 掌握度模型 | 移植自原工程 `server/study/profile-updater.js`：诊断基线 = 正确率 × 75；证据量门槛 ≥2 题；稳定区间 [40%, 80%) 不调整；单次变化 ±8；钳制 0-100 |
| `plan.ts` | 7 天计划生成 | 薄弱优先 + 先修闭包选点；链连续性排序；确定性；可解释理由 |
| `tutor.ts` | 演示知识库检索 | 关键词整体命中（权重 3）> 标题（3）> 知识点名（2）> 正文（1）；阈值 4；未命中明确降级 |
| `state.ts` | 状态归约 + 持久化 | 纯函数归约（submitDiagnosis/submitPractice/togglePlanTask/appendChat）；版本化序列化；损坏数据安全降级 |

### 2.3 状态层 `src/stores/learning.ts`

- 唯一状态源：`LearningState`（诊断作答、知识点掌握度、练习记录、计划完成度、对话、事件流水）。
- 初始化时从 localStorage 加载，失败/损坏时降级为初始状态。
- 深度 watch 自动持久化；存储不可用（隐私模式）时降级内存存储并在页脚提示。

### 2.4 视图层 `src/views/`

8 个路由视图 + App 壳（左侧导航 + 主内容区 + 移动端抽屉）。所有派生数据（画像分组、计划、推荐问题）由 store 计算属性产出，视图无业务逻辑。

## 3. 核心算法

### 3.1 掌握度更新（证据驱动）

```
诊断：baseline = round(正确率 × 75)          # 一题不定生死
练习会话（某知识点 n 题，c 对）：
  n < 2                → 不调整（证据量不足）
  0.4 ≤ c/n < 0.8      → 不调整（稳定区间，过滤噪声）
  c/n ≥ 0.8            → +round(8 × (rate-0.8)/0.2)，钳制 100
  c/n < 0.4            → -round(8 × (0.4-rate)/0.4)，钳制 0
每次变化写入 history（before/after/reason），界面可追溯。
```

### 3.2 计划生成（确定性）

```
1. 选点：知识点按掌握度升序；从最薄弱者开始，连带其先修闭包选入（容量 5）；
   闭包放不下则跳过，尝试下一个薄弱点。
2. 排序：先修在前；同轮候选优先「能解锁链上后续薄弱点」的知识点（链连续性）；
   其次按掌握度升序；最后按 id 平局裁决（保证确定性）。
3. Day 1-5 为选入知识点的专项任务（薄弱→「专项学习 + AI 讲解」，其余→「针对性练习」）；
   Day 6 综合项目；Day 7 综合测评。
4. 每个任务附带推荐理由（引用掌握度、最近测试、先修状态）。
5. 掌握度变化 → 计划自动重生成 → 页面展示变化摘要。
```

### 3.3 导师检索（演示模式）

```
分词：中文二元滑窗 + 英文数字词
评分：关键词整体命中查询 +3；命中标题 +3；命中知识点名 +2；命中正文 +1
阈值：≥4 才返回卡片；否则明确降级（列出可问范围，不编造）
响应：讲解 + 代码示例 + 常见错误 + 关联练习 + 引用依据 + 命中词项 + 追问建议
```

## 4. 状态与持久化

```typescript
LearningState {
  version, courseId,
  diagnosis: { answers, submitted, submittedAt },
  kpStates: Record<kpId, { mastery, diagnosis, practiceCount, practiceCorrect, lastResult, history[] }>,
  practice: Record<kpId, Record<exerciseId, choice>>,
  planCompletion: Record<taskKey, boolean>,
  chat: TutorMessage[],     // 含引用依据与结构化内容
  events: LearningEvent[]   // 诊断/练习/任务完成流水
}
```

- 存储键：`astripath.demo.v1`；版本不匹配或结构损坏 → 安全降级为初始状态。
- 重置演示：清除存储并恢复初始状态（首页/侧栏均提供入口）。

## 5. 部署架构

- 构建：`vue-tsc --noEmit && vite build` → `dist/`（约 690KB，gzip 约 190KB）。
- 托管：Qoder Sites 静态托管，`spa: true`（深链接 fallback），公开访问，无后端/无密钥/无数据库写入。
- 设计集成：样式消费 Nudge 设计变量（`--site-bg/fg/accent/surface/muted/border/font/radius` + spacing/typography/motion 缩放），已通过设计工作台注册 8 个页面与全部 5 项能力。

## 6. 安全设计

- 无任何密钥（前端不存 API Key）；无管理员接口；无真实个人信息；无支付。
- 演示数据全部虚构并标注；AI 能力边界明示（演示模式 + 引用依据 + 超范围降级）。
- localStorage 仅存设备本地演示状态，不构成数据暴露面。
